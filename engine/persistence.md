# 持久化与恢复协议（唯一执行规则）

适用：首次发卡、答疑、重讲、推进、续学与结课。这里规定写入顺序和异常处理；其他文件只引用，不另定一套恢复规则。这是模型执行纪律，不是自动事务程序，也不承诺硬盘损坏后仍能恢复。

## 1. 文件职责与稳定身份

- `当前任务卡.md`：唯一活跃卡，保存完整可重发正文。只在换卡、重讲修订或结课时原地更新。
- `进度.md`：进度真相源，保存当前卡 ID、任务版本、覆盖单元列表、固定档案相对路径、课程状态、掌握证据、待完成写入。
- `card-archive/C0001.md`：一卡一份永久知识档案，首次发卡前创建；文件名使用独立卡 ID，不使用可变主题。主题只是元数据。
- 卡 ID 单调分配、不复用；分配前检查进度和档案目录中已有 ID，不能仅用单元号推算。新教学任务、新拆分卡、独立复习卡用新 ID；同一卡的追问、重讲、改主题沿用原 ID 和路径。卡可覆盖多个单元，明确记录列表。拆分不重编号旧单元，新增单元使用未用过的 ID，记录前驱与来源。

## 2. 永久档案内容与实时整理

每份档案至少包括：卡 ID、主题、覆盖单元、创建时间、任务版本、最新任务全文、知识点讲义、掌握证据与待解问题、修订说明。任务全文必须足以恢复当前卡正文，不能只存摘要。

- 每次答疑完成内容核实后，**在本轮结束前立即实际写入**：先读对应知识片段，补充/澄清/修正该片段；只有全新主题才新增片段。重复问题没有新知识时更新该片段的理解状态或复核日期，不复制问答流水账。
- 保留有效知识和重要判定历史，允许整合重复措辞、重组片段；实质结论改动保留日期、旧结论、新结论及原因。不是要求文字只能追加。进度中只保存必要的卡点摘要、掌握证据和档案定位，不再复制整篇答疑。
- 普通答疑只更新知识片段，不改变任务正文和任务版本。重讲或修改任务正文时，先在同一档案内保留此前任务版本，再保存新版本的完整正文，随后同步当前卡；不新建活跃卡或另开档案。
- 任何写入后读回核对；失败如实告知“尚未保存”，保留待完成状态，不声称已落盘、不继续推进。已写入的同一操作重试时先核对，不重复添加知识、完成记录或版本。

## 3. 可恢复的写入顺序

多文件写入不视为原子操作。一次操作使用固定操作 ID（卡 ID + 目标版本 + 操作类型）；重试沿用它。

1. 读当前进度、卡和对应档案，先完成恢复检查。核对磁盘没有出现另一会话的新版本；发现变更停止覆盖，重新核实。
2. 在 `进度.md` 的“待完成写入”登记操作 ID、操作类型、旧卡/版本、目标卡/版本/档案路径、覆盖单元、目标课程状态、完成或跳过的依据；**若本操作要更新 `能力边界.md`，同条登记其待写 delta（哪个 strand 的哪个字段、旧值→新值、证据、日期，按 `map/capability.md` §4），使中断后能凭登记恢复，不依赖丢失的对话记忆。**此时不推进已提交的当前指针，不提前记为已掌握。
3. 先保存旧卡的有效任务版本、知识与证据，再写目标档案：首次发卡创建任务全文；答疑调整片段；重讲保存新任务版本；推进创建下一卡档案；结课保存最后一张卡的完成状态。读回验证完整。
4. 从已验证的目标档案同步唯一 `当前任务卡.md`（普通答疑且正文未变时不重写卡）。读回核对 ID、任务版本、覆盖单元、正文。
5. 更新进度、计划与索引，按操作 ID 去重：提交目标指针/版本/档案路径及课程状态，记录真实的掌握或未验证状态；同步维护学习目录里的 `能力边界.md`（`map/capability.md` §4，按步骤 2 登记的 delta 更新对应 strand、带日期与证据、旧判定留痕），并读回核对。完成上述核对后才把“待完成写入”置为“无”。
6. 才在对话中展示落盘的当前任务卡正文；普通答疑正常回答，不必重发整卡。必要的进度说明放卡正文外。

## 4. 续学与中断恢复

续学先完整读进度要求的已学记录，**再读当前卡及其对应的未完成卡档案（包括知识片段与待解问题）**，不能只读已完成档案。

- 有待完成写入：按登记的目标核对各文件，**并核对 `能力边界.md` 是否已按登记的 delta 更新**（已更新则去重、不重复追加；未更新则用登记里的旧值→新值/证据/日期补齐，不凭猜测重建）。目标档案完整且旧卡内容已安全保存时，从该档案继续完成步骤 4–5；缺失则从旧卡/旧档案恢复已提交状态，保留待完成说明并重试未完成步骤。没有完成证据，不能补写“已掌握”。遇到无法判断的冲突先报告并询问，不擅自推进。
- 无待完成写入：比对进度、当前卡、档案的 ID、任务版本与覆盖单元。相同才原样重发；不一致先核实，不能机械按指针或“最新修改时间”覆盖。
- 当前卡缺失/为空：优先从进度指向的档案中匹配任务版本的完整正文恢复；档案有更高但未提交版本时先排查中断，不直接选它。
- 当前卡存在而档案缺失：由当前卡补建对应档案，保留已有卡点记录；明确说明无法凭空找回未落盘答疑。
- 两者都缺失且没有其他可核实任务全文：告知原文无法恢复，再按确认的进度重建，标记“重建版本、不能保证与原卡逐字一致”。
- 源码已变化时保留原文、说明定位可能过期，核实后按重讲修订流程更新，不悄悄改历史。

## 5. 掌握判定与结课

- “看完了/继续/OK/懂了”只表明阅读完成或自报理解，不能单独写成已验证掌握。用简短自测、复述关键因果或实际观察结果验证当前目标，并记下证据；未验证不加入已会清单。已验证的目标不重复考。
- 用户明确要求跳过验证可以继续，记录“跳过/未验证”和待复核项，不计入已掌握；仅一句“继续”不足以自动跳过验证。
- 部分掌握只记录有证据的部分；剩余拆分为新单元/卡，保留来源关系，按步骤 3 的协议换卡，不能把原覆盖单元全部勾成已掌握。
- 最后一张卡完成且无未完成目标时不生成下一张：按同一写入协议补全最后档案，将唯一当前卡标记“已完成、无下一任务”并保留任务正文，课程标记“已结课”。若仍有跳过项则标记“流程结束、待复核”，不能宣称全部掌握。
- 结课后续学报告完成状态和可查阅档案，停止发卡。仅主人明确提出新学习目标或复习任务时才创建新卡，旧档案永久保留。
