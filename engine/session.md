# engine · 进门分流（首次建课 / 续学）

> 来源：原 SKILL.md 第一、二、三节（触发、首次建课、续学），原文完整迁移。

## 一、触发：「开始学习」（精确四个字）

收到这四个字，或"开始/继续学某项目源码""按单元精读"，**严格按下列顺序执行，不得省略、不得跳步**：

1. **定位项目根目录**：从用户指明、当前工作目录、或既有记忆判断。存在多个候选且无法确定时，用一句话问清（这是本流程唯一允许的开头澄清）。
2. **确定并确保学习记忆目录存在**（下称"学习目录"）：
   - **先读项目记忆索引**（`<项目根>/memory/MEMORY.md`，或 IDE projects 缓存下对应 slug 的 `memory/MEMORY.md`；不存在就跳过）。若其中记有"学习目录 = X"，**直接沿用 X**——续学靠这行定位改名后的目录。
   - **默认名 `<项目根>/.learning_memory/`**（带点前缀的隐藏目录，让本 skill 创建的目录在项目根层级默认隐藏）。检查它：
     - 不存在 → 创建 `.learning_memory/` 并使用；
     - 已存在且**带本 skill 标记**（目录内有 `进度.md` 且开头带本 skill 头部，或有标记文件 `.code-companion`）→ 是本项目先前建的，直接使用；
     - 已存在但**不带标记** → 判定为其他来源的同名目录（名冲突）。**绝不往里写任何东西**，改用备选名。
   - **备选名**：`<项目根>/.learning_memory_tutor/`；若也冲突，依次 `.learning_memory_tutor2`、`.learning_memory_tutor3`……直到找到不存在或带标记的目录。改名只影响学习目录名，不影响教学规则。
   - **创建后立刻打标记并记账**：在新目录写入标记文件 `.code-companion`（一行说明：由 code-companion 创建 + 选定的目录名），并把最终目录名记入项目记忆索引的进度摘要一行（如 `学习目录：.learning_memory_tutor`）。这样后续「开始学习」能定位到改名后的目录，不会再去碰源码目录。
3. **读取该目录，查看是否有文件**：列出并读取其中内容，判断属于下列哪条分支：
   - **A. 空目录 / 无任何计划文件** → 走 **第二节「首次建课」**（摸边界 → 规划 → 划分周/天单元 → 落盘），完成后从第一个单元发卡。
   - **B. 有进度真相源与计划文件** → 走 **第三节「续学」**。
4. 两条分支最后都汇入 `engine/card-loop.md` 的「发卡与停下」。

## 二、首次建课（学习目录为空）

顺序固定：**通读源码 → 摸边界 → 共同规划 → 划分周/天单元 → 落盘 → 发第一张卡**。规划期间**不发任务卡、不推进**，主键是和主人一起把课建起来。

**2.1–2.4 的建课流程**（通读源码 → 摸边界 → 共同规划 → 划分周/天单元）**是单一真相源，见 `map/build.md`**——这里不再重复，避免两份分叉。依次走完 build.md 的 2.1/2.2/2.3/2.4 后，回到下面的 2.5 落盘发首卡。

### 2.5 落盘并下发首卡

把建课结果写进学习目录与项目记忆，再发第一张卡：

- 初始化**进度真相源**（模板见 `map/progress.md`）：写入目标、边界地图（各 strand 地板/天花板/误解）、依赖地图、周/天单元计划表、当前指针 U001。
- 写一份**学习计划/总纲**文档：依赖地图 + 周/天单元表 + 每单元的主题与自测题方向。
- 更新项目记忆索引的进度摘要一行。
- 建立**任务卡档案**子目录（学习目录下 `card-archive/`），存放各卡永久档案。
- 读取 `engine/persistence.md`，为 U001 分配独立卡 ID（新课从 C0001 起），登记固定档案路径与覆盖单元。按该协议先落盘档案全文、唯一当前卡及进度并读回验证，再按 `engine/card-loop.md` 展示首卡。不得先发卡后保存。

## 三、续学（学习目录已有文件）

1. **读记忆索引**：读项目记忆索引（`MEMORY.md` 或 IDE projects 缓存下对应 slug 的 memory），再读其中「教学规则」与「进度摘要」。
2. **读真相源与全部已学记忆**：读学习目录里的进度真相源与计划文件；**完整读「已完成单元清单」「已会知识清单」「卡点与答疑记录」**（不只依赖摘要），据此掌握主人真实学到哪、已经会了什么。取当前单元指针、边界地图、依赖地图。
3. **先恢复，再发卡**：必读 `engine/persistence.md` §4。读取唯一 `当前任务卡.md` 以及进度指向的当前卡永久档案（包括未完成卡的知识片段、答疑与待解问题）；检查待完成写入、卡 ID、任务版本和覆盖单元。一致才原样重发；不一致先恢复，不机械信任任一文件。当前卡缺失时优先从对应档案恢复完整正文，两者均无可用原文才告知并重建。已结课或流程结束待复核时报告状态，停止发卡；新目标/复习须由主人明确提出。
4. **具体复述上次位置**：用 1–2 句**具体**的话复述——上次完成到哪个单元 ID、读到哪个文件的哪几行、当时得出的结论是什么，再报「已完成 / 剩余 / 当前单元」与动态估算。**禁止**"上次我们聊到一些内容"这类模糊说法。
5. 汇入 `engine/card-loop.md`（续学重发已通过恢复检查的 `当前任务卡.md`，不另起新卡；已结课/待复核按终态停止发卡）。

> 若真相源存在但内容显示"未开始"或覆盖不完整，按第二节补齐建课，不带着残缺计划续学。
