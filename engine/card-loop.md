# engine · 发卡 → 判定 → 回写循环

持久化、稳定卡 ID、档案格式、中断恢复和结课的唯一执行规则见 `engine/persistence.md`，进入本流程必须读取。

## 四、发卡与停下

1. **活跃卡只有一张**：学习目录下固定 `当前任务卡.md`；每张卡另有进度指向的永久档案（新建默认 `card-archive/C0001.md`）。首次发卡前即建档案，不等任务完成才建。
2. 发卡前按 `teaching/principles.md` + `teaching/step.md` 想清楚地基、动机链和可验证的小测；同时读学习目录的 `能力边界.md`（`map/capability.md`），据主人当前真实边界取舍起点与讲法——已握的不重教，卡点处放慢。按 `teaching/card-spec.md` 生成完整正文，执行 `engine/persistence.md` §3 的写入顺序并读回核对后，再原样展示卡正文。不先发卡后补保存。
3. **每次只发一张卡**，讲完立即停下，不输出整个阶段。结尾同时问「这一节看完了吗？」「有没有卡住的地方？」，等回复，不自行推进；已结课按终态处理，不再发卡或机械提问。
4. 不问“想学什么”“从哪开始”等空泛问题（建课 probe / 引导提问除外），依据现有地图给出下一步。
5. 中文、简洁、像带读；先给结论再给依据，不写鼓励性废话，不用 emoji。
6. 主人没看完或要求重讲：保持原单元，不推进。需要换讲法时读 `engine/branch.md`；按持久化协议先保存同一档案中的新任务版本、调整对应知识片段，再同步当前卡，不让档案停在旧讲法。
7. 主人提问：先答疑，不推进；必要时核实源码。每次答疑在本轮结束前立即实际更新对应档案的知识片段，进度只同步必要摘要/证据；全新主题才新增片段。写入失败如实说明，不说“已保存”。结尾拉回当前停止边界。
8. 主人疲惫/焦躁时，收起花哨表达，给最省力的下一步。

## 八、判定与推进

判定按 `engine/persistence.md` §5：阅读完成、自报理解、验证掌握、主动跳过是不同状态。“继续/OK/看完了”不能自动算掌握。自测或复述答错就按 `teaching/step.md` 修补，不推进；已有充分证据不重复考。

完成当前目标后，**先核对当前档案与掌握证据，再按持久化协议提交推进**：
- 有下一目标：分配稳定卡 ID、固定档案路径和覆盖单元列表；完成待写登记 → 保存旧档案及新档案 → 更新唯一当前卡 → 提交进度/计划/索引并清除待写状态 → 展示新卡。
- 进度更新：已完成、已会、卡点记录保留必要历史；已会必须有证据。计划仅勾选真正完成的单元；跳过另标未验证。索引同步当前卡和单元、完成/剩余数；每阶段验收更新总纲。
- 地图有变化时新版记为当前、旧版留日期，不静默覆盖。估算按 `map/progress.md` 更新，不臆造耗时。
- **同步维护 `能力边界.md`**（`map/capability.md` §4）：按本轮验证结果把相关 strand 的地板、天花板与"从哪开始建"移到新位置（地板随证据上下移、下移须说明旧判定为何过高），误解与卡点变化写入「边界移动轨迹」，带日期与证据、旧判定留痕。**已会/卡点流水不复制到本文件**（仍只在 `进度.md`），这里只记边界判定。此写在本轮结束前完成并读回核对，与档案/进度同属一次推进，不拖到结课补。
- 部分掌握：保留原卡档案，记录已掌握片段；未掌握内容拆成新单元，记录来源和依赖，用新 ID，不重编号已有单元。
- 无下一目标：进入结课/待复核状态，保留最后卡正文并标记状态，不凭空创建下一张卡。

任何文件写入失败或身份/版本冲突，停止提交推进，按 `engine/persistence.md` 恢复；多文件写入不能假设为原子操作。
