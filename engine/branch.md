# engine · 三个分支（答疑 / 重讲 / 重夹逼）

> 来源：原 SKILL.md 中散在发卡规则、教学法内核里的分支处理，按功能归拢。

## 分支一：主人提问（答疑，先答后拉回）
- 主人提问：**先答疑、不推进单元**；必要时用工具核实源码，回答里带 `文件路径:行号`。
- 必读并执行 `engine/persistence.md`：每次答疑在本轮结束前立即更新进度指向的固定档案。先读已有知识片段，同主题就地补充/澄清/带痕修正，全新主题才新增；重复问题仅更新理解状态或复核日期，不硬加流水账。进度只同步必要摘要和证据。档案缺失先按恢复协议补建；写入后读回，失败如实说明，不等下一轮或卡完成才保存。
- **同步维护 `能力边界.md`**（`map/capability.md` §4）：答疑暴露的误解、卡点、思考痕迹写进对应 strand 的「误解 / 不稳」与文件的「边界移动轨迹」，带日期与证据；修正旧结论保留旧痕。重复问题无新信息时只更新该条理解状态或复核日期，不堆问答流水账。与档案维护同在本轮完成。
- 答复结尾把主人**拉回当前停止边界**——答疑后可以拉回边界，不能顺势把下游讲完。

## 分支二：主人说"没看完 / 再看一遍"（重讲）
- 保持原单元，**换一种讲法**：换例子 / 画图 / 给公式 / 拆更小段，不推进。先按 `engine/persistence.md` 在同一固定档案中保存任务修订版本并调整知识片段，再同步唯一当前卡，核对后展示；沿用卡 ID，不新建档案。
- 若重讲中澄清了旧误解或暴露新的边界信息，同步维护 `能力边界.md` 对应 strand 与「边界移动轨迹」（`map/capability.md` §4，带日期与证据、旧判定留痕）；单纯换讲法而无新能力证据则不改边界。
- 若回答让你不确定他的边界到底在哪条线上，**重新夹逼**（见分支三）再选下一步。

## 分支三：边界不清（重夹逼）
- 从他握着的到他没握的，跑一小串问题——**一次只问一个**，每个问题都要移动某条边界。
- 不问废话、不问上一答已回答过的、不退回已夹逼过的区域。
- 答对且自信 → 大幅上调；答对但犹豫 → 温和上调并刻画不稳；答错 → 天花板下移、收窄夹逼；一次失误只是一个坐标，在附近再探，挖误解波及范围。
- 夹逼细节见 `teaching/step.md` 与 `map/build.md` 的二分夹逼法。
- 重夹逼得到的新地板/天花板坐标同步写入 `能力边界.md` 对应 strand（保留前一坐标作历史，见 `map/capability.md` §4）。

## 分支四：主人明显疲惫 / 焦躁
收起花哨表达，直接给最省力的下一步（仍不越过停止边界）。

## 部分弄懂
只记录已弄懂的片段，把剩余部分**拆成新单元插入序列**（剩余数相应增加），下一张卡只讲拆出来的最小片段。
