# map · 能力边界档案（主人的实时能力画像）

> 首次建课 probe 结束时建立，整个学习过程持续维护。它是**当前能力判定的唯一真相源**：记主人"现在实际能握什么、卡在哪、边界移到哪"。`进度.md` 是进度与身份的真相源（学到哪、当前卡 ID/版本、待写状态）；它里面「目标与边界地图」一节是**建课时的初始快照**，不是与这里竞争的当前真相。两类事实各归其位：能力判定看本文件，进度身份看 `进度.md`。

## 一、它是什么、放哪

- 固定文件名 `能力边界.md`，住在 `engine/session.md` 进门第一步选定的学习目录内（默认即 `<项目根>/.learning_memory/能力边界.md`；名冲突时是备选目录里的同名文件）。学习目录是隐藏目录，不干扰源码。
- **只有一份**、原地更新（与 `当前任务卡.md` 同样只此一份）；按固定文件名定位，不按主题改名、不拆多份、不做归档清理。
- 归属：学习目录内的教学文档，**不改源码**。它是 skill 的产物，不写进主人自己维护的笔记目录（除非主人明确要求）。

## 二、建立时机（首次建课）

1. 先走 `map/build.md` 的 2.2 摸边界：对每条 strand 二分夹逼出地板 / 天花板 / 误解 / 从哪开始建，并把目标问具体、把时间周期 / 学习范围 / 顺序偏好问清。
2. **这些提问全部结束、收束边界地图之后，把结果落盘成 `能力边界.md`**——不在 probe 中途边问边写，也不等发完第一张卡才补。probe 的结论先变成文档，再进入 2.3 共同规划。
3. 写入后立即读回核对（strand 齐全、日期与来源标注完整）；`engine/session.md` 2.5 落盘时再核对其存在与完整，才算建课落盘完成。

**特殊情况**：续学时若学习目录有进度真相源却缺 `能力边界.md`（老课程遗留，或文件丢失），按**本节规则补建**，不带着缺失往下走。补建依据：优先读进度真相源的「目标与边界地图」建课快照、已会清单、卡点与答疑记录还原当下边界；信息足以还原的部分直接落盘并标记"（重建于 YYYY-MM-DD，依据……）"。**若信息不足**：这是续学阶段的例外澄清，不属 `SKILL.md` 的"唯一允许的开头澄清"——它发生在进门分流之后、为恢复必需文件而问，配额独立。仍严格一次一问（沿用 `map/build.md` 2.2 夹逼节奏），只问还原边界所缺的最小问题；**绝不臆造主人的能力**。补建完成才继续续学。

## 三、模板

```text
# <项目名> · 能力边界（主人的实时能力画像）

> 首次建课摸边界后建立；学习全程持续维护。当前能力判定以本文件为准。
> 进度身份/已会流水/卡点流水见 `进度.md`，本文件不复制，避免双真相。
> 所有判定带日期与来源；改结论留旧痕、不静默覆盖。

## 当前目标（probe 收敛后的表述）
- 目标：（想学到什么程度、能做什么；主人原话尽量保留）
- 记录：YYYY-MM-DD · 主人亲口 / 我推断

## 编排信息
- 学习时间周期：（每次能投入多少、整体想用多长；仅作规划视图，不构成催促）
- 需要学习的部分：（全库通读 / 聚焦某模块主链）
- 学习顺序偏好：（先全局感 / 先跑通主链，有无急着要用的部分）
- 记录：YYYY-MM-DD · 主人亲口 / 我推断（确认阶段若有改动，按新日期留痕）

## 各 strand 的当前边界
### strand A：<这条线是什么>
- 地板（稳定答得出）：YYYY-MM-DD · 具体是什么、当时的证据（自测/复述/实测）
- 天花板（答不出/答错）：YYYY-MM-DD · 卡在哪一层、误解是什么
- 误解 / 不稳：YYYY-MM-DD · 思考痕迹、信心高低、波及范围
- 从哪开始建：YYYY-MM-DD · 下一站
### strand B：……
（每条线一段；新 strand 追加，不删旧 strand）

## 边界移动轨迹（只追加，不静默覆盖）
- YYYY-MM-DD · U<n> / 答疑 / 重夹逼：strand A 地板 X → Y（证据：……）；旧判定保留
- 地板下移时写明为何旧判定过高（证据），不因预感调整

## 关联指针（不复制）
- 进度身份、已完成/已会清单、卡点与答疑流水、待完成写入：`进度.md`
- 地图依赖版本与历史：`进度.md` / `地图历史.md`
```

## 四、持续维护（整个学习过程都要改它）

这份文档是活的：每次拿到关于主人能力的新证据，就在**本轮结束前实际写入**，不等结课、不攒着补。

- **通用纪律**：写入后读回核对；写失败如实告知"尚未保存"，保留待处理，不声称已落盘、不继续推进。同一操作重试时先核对已写入内容，不重复追加条目。允许整合重复措辞、重组片段，但实质结论改动必须保留日期、旧结论、新结论与原因。
- **发卡前**（`engine/card-loop.md`）：读 `能力边界.md`，据主人当前真实边界取舍起点与讲法——已握的不重教，卡点处放慢。
- **推进 / 验证掌握后**（`engine/card-loop.md` 第八节、`engine/persistence.md` §3 步骤 5）：把相关 strand 的地板、天花板与"从哪开始建"移到新位置，追加边界移动轨迹，带日期与证据。**地板随证据移动**：上移要有验证证据；若证据证明旧地板判高了，带证据下移并留痕说明理由，不因预感随意调整。
- **答疑 / 重讲时**（`engine/branch.md`、`engine/persistence.md` §2）：主人暴露的 misunderstanding、卡点、思考痕迹写进对应 strand 的「误解 / 不稳」与「边界移动轨迹」；修正旧结论带日期留旧痕。重复问题无新信息时只更新该条的理解状态或复核日期，不堆问答流水账。
- **重夹逼时**（分支三）：新测出的地板 / 天花板坐标更新到对应 strand，保留前一坐标作为历史。
- **地图演进同步**（`map/evolve.md`）：边界地图改版时，`能力边界.md` 同步为新版当前判定；旧版判定在本文件内带日期留档或进入 `地图历史.md`，不抹掉。`进度.md` 的边界节保持建课快照原样——那是刻意的快照，不是漏更新，也不与这里互相覆盖。

## 五、不遗忘

- `能力边界.md` 原地持续更新，只增不删、不设 archive、不清理；「边界移动轨迹」只追加有证据的条目。
- 课结了它仍留在学习目录，是主人这份能力画像的完整历史；续学先读它再发卡（见 `engine/session.md` 第三节）。
- 它记录的是**关于主人的事实与判定**，主人有权查看。
