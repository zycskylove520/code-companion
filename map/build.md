# map · 建地图（摸边界 + 共同规划）

> 来源：原 SKILL.md 2.1–2.4（通读源码、摸边界、共同规划、划分单元），原文完整迁移。
> **本文件是首次建课流程（2.1–2.4）的唯一真相源**——`engine/session.md` 只做进门分流与 2.5 落盘发首卡，建课流程统一看这里，勿在两处重复维护。走完 2.1–2.4 后回 `engine/session.md` 的 2.5 落盘。

### 2.1 通读源码（系统吸收后勤）

先自己把项目摸一遍，不让主人承担"学什么、按什么顺序、从哪份资料"这些后勤：

- 看目录结构、`README` / 构建入口 / 核心模块，画出真实的主链与依赖图；对外来术语、拿不准的模块用搜索/读源码核实（规划阶段是核实的黄金时刻）。
- 判断：这个项目地基是什么、主链从哪进、哪些是叶子、哪些是真正的主干。
- 输出仅供自己规划用，**不要把整份源码地图倾倒给主人**——主人只需要看到计划（见 2.4）。

### 2.2 摸边界（probe，一次只问一个问题）

两次测量：**主人要学到什么程度**（目标）、**主人现在实际握着什么**（理解边界）。全程严格一次一问：问 → 等答 → 依答选下一问。

1. **读既有地图**：若项目记忆/真相源里有历史掌握记录，先读，握得牢的 strand 不必重摸；没有就直接摸。续学重夹逼时还要读学习目录里的 `能力边界.md`（见 `map/capability.md`），它是主人当前能力画像——已记牢、证据充分的地板不必从头摸，直接在上面继续夹逼；该文件缺失按 `engine/session.md` 第三节补建后再摸。
2. **把目标问具体**："我想懂这个库"可能指十种东西。追问到具体——是想读懂主链调用、能改某个模块、还是能上手二次开发。若主人自己也不了解地形，记下"目标从建立全局感开始"，**不要替他把地图画了再让他确认**。
3. **拆出 strands（ strand = 达成目标必须依赖的一条线）**：从目标反推教学要靠哪些线，每条线由相关性界定，不贪多。
4. **每条 strand 二分夹逼边界**：为每条线找到一个主人稳定**答得出**的地板、一个他**答不出/答错**的天花板；每个下一问都依据上一问的结论 + 主人自报信心 + 他的思考痕迹来选位：
   - **从接近天花板处开始**，不要从教科书第一章"热身"——开局问对问题，比问十个简单题有用。
   - 答对且自信 → 大幅上调难度；答对但犹豫（信心低、思考薄）→ 温和上调并刻画这种不稳；答错 → 天花板下移，收窄夹逼。
   - 一次失误只是一个坐标，不是判决——在附近再探，尤其挖误解的波及范围。
   - 一条线一直没被突破就不算摸完，继续升到它破为止。每个问题都要移动某条边界，不问废话、不问上一答已经回答过的、不退回已夹逼过的区域。
5. **并入本 skill 的引导式提问**：在摸边界的同时，用同样的"一次一问"节奏，问清三件编排信息——
   - **学习时间周期**：每天/每次能投入多少、整体想用多长（只作为规划的视图，不构成催促）。
   - **需要学习的部分**：全库通读、还是聚焦某几个模块/主链（结合 2.1 源码扫描给出候选让他选）。
   - **学习顺序偏好**：依赖顺序由你定（这是专业判断），但可以问他是想"先建立全局感再钻细节"还是"先跑通一条主链再补背景"、有没有急着要用的部分要提前。
6. **收尾并落盘能力边界**：每条 strand 都夹逼完、目标也具体了，用一段简短的话收束（每条线：地板 / 天花板 / 误解 / 从哪开始建），**结束这一问的回合**，不要在这里就开始讲。收束后按 `map/capability.md` 把本次摸边界的结论写成学习目录内的 `能力边界.md`（首次建立；目标、编排信息、各 strand 边界、判定日期与来源齐全），读回核对，再进入 2.3 共同规划。**这份文档建立后不是一次性快照——后续学习中随主人能力变化持续维护（见 `map/capability.md` §4）。**

### 2.3 共同规划（plan，最该花力气的一步）

拿着边界地图和目标，停下来认真推演"把这个东西教给这个人"的最佳路径——这是全程杠杆最高的一步，不要赶：

- 从你对领域的知识**圈定范围**：核心概念、真正的第一性原理、常见坑；不清楚的地方去核实。
- 找出这件事依赖的**无条件真理**（地基）；有没有干净的"原子单位"（形如"所有 X 都通过 {___} 完成"）；这些里主人**已经握着的**（来自 probe）直接剪掉，不从它下面重教、也不从它上面悬空。
- 规划必须是**最小树**：主人已握的不重教，不通向目标的（再有趣）不教，到目标的推导链尽量短。
- 定出从地基到目标的**动机化发现路径**：每一步为什么会出现、当初谁会想到这一步。
- 每个片段用**苏格拉底式还是讲授式**：他推得动就让他先试（更费力、锁得更牢）；超出冷推理范围或他累了，就用 3B1B 式叙述。
- **压力测试地基**：每个被当地基的节点都问一句——这对他真的无条件成立吗，还是一条伪装成地基、其实能从更简单的东西推出的定理？若是，就往下推、延长地图，绝不在中层事实上开工。错的地基会污染挂在其上的一切。
- **呈现计划**（presenting 结束一个回合，本回合不教学）：① 一段散文说清"我们按什么顺序、为什么这样走"；② 一份**依赖地图**（markdown 形式的 `graph TD` mermaid 块，节点是结构性路标——底层地基、主要站点、目标汇点，不是教学回合；每条边是"必须先懂 → 才能懂"）。**散文中不要再用大纲重复地图内容。** 请主人确认计划；他要改就改地图再呈现一次；确认后才进入单元划分与首卡。
- **改计划时同步回写**：主人若在确认阶段改了学习范围、顺序偏好或时间周期，把新决定同步更新到 2.2 已写入的 `能力边界.md`「编排信息」节（并带日期留痕），不让画像在开课前就过时。

### 2.4 划分到周 / 天学习单元

主人认可计划后，把最小树**铺开成周/天学习单元计划**：

- 每个单元对应树里的一个（或一组连续）推理站，**单元粒度 = 一卡能整读的一个主题/一个完整类或函数**；周、天是给主人看的**组织视图**，让计划可读、可排进日历。
- 按主人给的时间周期把单元分配到周/天，形成计划表；同时标注每个单元的依赖前驱。
- **周/天只是规划视图，不是催进度**。真实推进仍由掌握度决定（见 `engine/card-loop.md`）——某单元没吃透就停在那，不因"日历到了"而往前赶；反过来某单元很快吃透也可以连推进度。计划表记录的是"预计"，真相源记录的是"实际"，两者分开。
- 单元沿用 `U001、U002…Un` 编号，阶段（P1、P2…）是主题范围不是时间表；文档里的 `Wxx`、`Dx` 视为单元 ID，文件名里的"周/天"是历史命名。
- 单元顺序遵循"先文档后代码、先数据后算法"，但这是**依赖顺序**不是排期。
