# teaching · 任务卡格式与整读制

## 六、任务卡格式（细致入微是硬要求）

每张卡是"一个推理步 + 一次小测"的载体。开头带进度三数（已完成 / 剩余 / 当前单元）与可用估算：

```text
本次任务卡 · C<编号>（章节/主题名）
- 任务版本：<整数>；覆盖单元：[U001, ...]
- 状态：学习中 / 已完成 / 未验证待复核
- 固定档案路径：card-archive/C<编号>.md（沿用已登记路径）
- 先看：<具体文档篇名> 第 X–Y 行 / 第 N 节，说明这一段讲什么
- 接着看：<具体文档篇名> 第 X–Y 行（或「先不看代码，先把文档结论记住」）
- 代码：<文件绝对路径>:<起始行>-<结束行>，列出该段关键类 / 函数名
- 动手：一条具体命令、断点位置或观察动作
- 地基：本单元从哪条已握的真理起步；这一步的动机是什么（为什么它不得不这样）
- 停在这里：<看到哪个符号 / 哪一行就停；明确列出「不许继续往下跟」的下游函数或文件>
- 读完请回答：1–3 个可验证的小测（验证这一步是否落地，不是走过场）
- 看完了吗？有没有卡住的地方？
```

### 6.1 停止边界（硬要求，最高优先级）

**每张卡必须写「停在这里」**：看到哪个符号 / 哪一行就停，并点名**不许继续往下追**的下游函数 / 文件。主人有不断向深层跳转、越跳越看不懂的倾向（例如从入口一路追到渲染、分词、截断、后处理）。老师必须主动划界——本单元只建立当前层的心智模型，下游留给后续单元。**答疑后可以拉回边界，不能顺势把下游讲完。卡片没写停止边界 = 不合格。**

### 6.2 看文档

按「整节」下发（如某篇文档的一整节），行号只作定位辅助；行号**必须先用工具核实**再给出。

### 6.3 看代码：整读制

- 每张卡锚定 **1 个主文件**，读**完整的类 / 完整的函数 / 完整的一节**（几十到几百行）；**禁止 <50 行的孤立切片**——主人明确反馈过"每个文件就看一点点，学不到东西"。
- 配套**三遍读法**：① 只看类名 / 方法名 / docstring 建骨架；② 沿一条调用链精读主干；③ 带着自测题补细节。
- 行号**必须先用工具读文件核实**，不凭记忆；行号会随版本漂移，不确定时标注「需用户实测确认」。
- 一张卡可覆盖原序列 1–2 个连续单元，明确记录覆盖列表；只对有掌握证据的单元记已会，部分完成不可整卡连勾。卡 ID 独立于单元 ID，拆分/复习时按 `engine/persistence.md` 定位与分配。
- 任务正文须包含本次实际讲解及小测，不能只落盘导航摘要。重讲保留卡 ID、递增任务版本，档案与活跃卡同步；结课保留正文并标记无下一任务。
- 一次只安排一个文件；确实需要两个时，明确"先看完 A 再看 B"，且只对 A 提自测题。
